# G4 and Kitchen-QK NVFP4 PV: controlled ABI-2 policies

The first ABI-1 G1 snapshot is separate. Parent reported its successful CUDA 13
build; that evidence does not cover these new sources. No GPU action was taken
here. The next revision needs compilation, instruction/resource inspection and
explicit tiny checks before benchmark promotion.
Parent also reported snapshot-1 tiny diagnostics passed on RTX PRO 6000; ABI-2
grouping/FP4 remains a separate validation obligation.

## Parent API

The root run_chunked option-first API and runtime.sol_attn_chunked accept:

| Field | Values / ownership |
|---|---|
| grouping_policy | none (default G1), g4 |
| pv_precision | int8 (default), nvfp4 (G4 + SM120 only) |
| grouping_schedule | all_steps (default), first_eval |
| evaluation_index | Explicit request-local sampler index; never inferred from sigma or shape |
| grouping_state | Caller-owned per-request/per-layer mapping; scope key identifies owner |
| center_values | Optional bool override; otherwise follow schedule |
| validation_context | Caller-owned ValidationContext for trusted model streaming |

Anemoi/combined extra fields such as precision_policy pass through the root;
pv_precision is VC-only. The parent may map int8_control/optimized to these
internal policies and map first_step to first_eval. No dispatcher/widget is
implemented in this subtree.

all_steps refreshes grouping and means/scales from current values. first_eval
clusters/centers on index 0, then reuses its permutation and disables centering
on later indices; scales always refresh. An explicit center_values overrides
that centering choice. G1 also supports first-evaluation-only centering, but has
no permutation to retain. Later uncentered values still use fresh local scales;
this is not a return to Kitchen's stale global-scale carrier.

For first_eval G4, pass a mapping with scope=(request_id,layer_id), retained in
the layer closure and cleared at request end. Internally it stores only the
permutation, valid-length identity/copy, scope/shape/stream/evaluation metadata,
and two device clipping counters. A missing first evaluation, changed scope,
shape/stream or live lengths, or backwards evaluation rejects reuse. No global
tensor cache. Same-layout reuse checks weak identity plus PyTorch version;
changed identity checks lengths once. Do not mutate lengths through raw pointers.

## Deterministic grouping

New vc_group_prepare.cu consumes original V from the current fused projection
chunk, after the original Kitchen producer finishes. Q is unchanged. Each
head/cube runs four Lloyd iterations with four seeds at
floor(g*(live_count-1)/3). Distances and centroid sums have fixed FP32 reduction
order; lowest cluster ID wins distance ties, empty clusters retain their center.
Stable (cluster ID, original slot ID) sorting defines newslot -> source.
Invalid slots follow all live slots in identity order. Protected key cubes use
identity order and zero means.

Sorted rows are partitioned into four contiguous 16-row quantization groups.
These groups need not coincide with unequal-sized clusters: this is a specified
cube-constrained grouping policy, not reproduction of the paper's undocumented
clustering settings. Tokens never move between cubes.

K codes and their paired FP32 scale/bias are copied losslessly into separate
fine buffers using Kitchen's physical perm_key mapping. Original K/V remain
available for protected queries and keys. Routing centroids, pooled Q/K/V,
thresholds/forced neighbors, route lists and original next K/V statistics remain
untouched. V grouping uses original BF16 values, never reconstructed INT8 values.

Metadata is BF16 means / FP32 represented scales [1,H,N,4,128]; permutation is
uint8 [1,H,N,64]. INT8 residual layout is [H,128,Tp] with Kitchen perm_d on keys.
NVFP4 residual layout is uint8 [H,128,Tp/2], natural sorted token order, low nibble
first. Per-16 UE4M3 V-scale codes are [H,N,128,4]. QK remains Kitchen INT8 with
original per-token scales even when PV uses NVFP4.

## Actual lower-bit arithmetic

G4 INT8 splits each 32-key integer PV MMA into two masked 16-key contributions,
applying that group's scale and represented-P mean restoration before the next.
This costs four K32 MMAs per output tile and is an arithmetic/quality control.

G4 NVFP4 instead packs P/V to E2M1 and executes a real SM120
mma.sync.aligned.m16n8k64 ... mxf4nvf4 ... scale_vec::4X instruction.
The instruction wrapper follows the Apache-2.0 Anemoi primitive; the score
fragment conversion, packing, denominator and mean handling are VC-specific.
Kitchen perm_key score fragments are explicitly shuffled into natural K64 MMA
A order; CPU tests enumerate every logical fragment coordinate against the
[NVIDIA m16n8k64 layout](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#warp-level-matrix-fragment-mma-16864).
Hardware layout/scale selector correctness still needs the GPU diagnostic.

P per query/K16 group: sP=E4(448*max(p)), P4=E2(2688*p/sP), zero scale -> zero.
Represented real mass is sum(P4*sP/2688). The numerator, denominator and mean
correction all use that represented mass, unlike Anemoi's pre-packing denominator.
They carry a common x255 domain to mix protected INT8 key blocks and preserve
the original pooled-tail handover. Both contributions rescale with the same
Kitchen running-max/block-max policy.

V per channel uses an explicit global calibration gV:

    estimated_vamax = original_Kitchen_vscale * 127 / 1.1
    gV = nextafter(max(2 * estimated_vamax / 2688, 1e-8), +infinity)
    sV[group,channel] = E4(absmax(residual) / (6*gV))
    V4 = E2(residual / (decode(sV)*gV))

This conservative channel-global calibration differs from a tensor-global
Anemoi scale and is recorded as a controlled VC policy. It is fresh on bootstrap,
stale on subsequent rolling calls, with the original clamp not invertible at zero.
NV PV applies gV[channel]*255/2688 exactly once; means restore the represented
P mass. Zero residuals/scales remain finite. Saturation is possible, especially
when stale statistics underestimate current values.

Native clipping_counts is uint64[2]: residual entries outside the global range
abs(R)>2688*gV or nonfinite, and groups outside that global range or nonfinite.
Normal RNE E4 microscales may round down so abs(R)>6*decoded(sV)*gV:
that is ordinary quantization saturation, NOT global calibration clipping, and
does not increment these counters. It remains visible in numerical oracle error.
Protected key cubes are excluded. Counters reset each traversal. Access through
prepared.grouped.clipping_counts or grouping_state["_native_vc_clipping_counts"].
They stay on device to avoid per-layer host synchronization; collect at explicit
diagnostic/benchmark boundaries. No automatic rescaling/fallback hides clipping.
run_chunked diagnostics exposes the same device vector as
vc_nvfp4_clipping_counts, with vc_nvfp4_clipping_count_names documenting both
entries. vc_nvfp4_calibration distinguishes fresh/stale original statistics and
explicitly records that this is a conservative bound, not measured residual absmax.

## Hooks, calibration and original ranking scores

prepare_chunked now accepts grouping_hook(t0,q,k,v,full_valid,perm_chunk,mean_chunk),
after native grouping on the current stream. Q/K/V are original bounded BF16
[1,H,M,128], not permuted/reconstructed operands. perm_chunk is [1,H,C,64],
mean_chunk [1,H,C,4,128]. The sibling backend may gather bounded K/V only; Q
stays natural. A partial final M may be zero-padded to 64 within that chunk.
chunk_hook remains unchanged and can be omitted when grouping_hook is used.

measurement_hook has the same seven arguments, but runs only during the existing
bootstrap measure traversal. G1 passes permutation=None and G1 represented means
with protected key means zero. G4 groups during that traversal; the final traversal
reuses the measured permutation while recomputing current means/scales, so there
is no second clustering pass. The hook supports actual original Q/K/V and
residual-V absmax collection without another projection or full floating QKV.
Its collector finishes before the existing calibration_hook; that closure can
finalize mixed-backend scales. Cached calls do not invent fresh measurements:
the sibling owner must maintain scoped rolling calibration and clipping counts.

original_route_scores(prepared) exports float32 [1,H,N,N], indexed by absolute
key ID, with the exact existing Kitchen proxy formula:

    dot_int32(cen8[query], kciP[key])
       * FP32(cens[query] * FP32(scale*LOG2E))
       * kcs[key]

Multiplication order is explicit FP32. Both carriers already use perm_d channel
order; no inverse or new mean/router is used. Scores are raw log2 logits, not
softmax probabilities. This optional export costs an extra 4*H*N*N bytes and an
INT8 dot pass; it must be priced in mixed-quota timing. Route selection is unchanged.

ValidationContext skips repeated layout host reads only for an unchanged tensor
identity/version/shape/device. K/V statistic finiteness is always asserted on
device on the trusted path; the default public diagnostic path retains host
validation. No finite-value result is cached for evolving tensors.

## Qualification and honest remaining limits

CPU suite tests deterministic clusters/ties/live support, K/scale pairing,
fragment mapping, represented means, INT8/NVFP4 algebra, empty groups, 1/17/63/64
live rows, max rescaling, state reset/reuse, mixed import isolation and the
measurement-hook order with exactly two existing traversals and no host reads.
Mocks test orchestration, not native arithmetic.

Explicit authorized GPU checks:

    diagnostics.tiny_check(grouping_policy="g4", pv_precision="int8")
    diagnostics.grouped_check(pv_precision="int8")
    diagnostics.grouped_check(pv_precision="nvfp4")

grouped_check compares actual native operands/output against an independent
CPU sparse oracle, checks stock prefixes/next stats and original route scores,
and includes unequal values/zero channels/outliers. It has not run here.
Tolerances are tiny-test diagnostics, not accepted production quality gates.

Remaining: compile new ABI 2, inspect microscaled instructions/resources/spills,
validate native mapping/rounding, measure clipping and drift, captured
route/coarse/tail equivalence, memory/lifecycle checks, first-evaluation schedule,
all-layer quality and complete-call/end-to-end timings. Extra original+grouped K
storage, G1 residual work still done by shared producer, clustering, hook copies
and correction overhead may outweigh lower-bit PV. Neither speed nor the <=5%
memory target is claimed. Unsupported: token augmentation, cross-cube clustering,
ExpCast, FP8-only PV, G1 NVFP4, and mixed precision transitions in VC-only loop.
